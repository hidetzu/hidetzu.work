# 数学ノートを作る

数学の思考と証明は本人が行い、Claude は編集・構造化・表示を担当する。入力の扱い、本人の証明の扱い、学習段階の区別、数学的な正確性は `.claude/rules/math-notes.md` に従う（`src/content/math/**` を開くと読み込まれる）。書式の仕様は README の「数学ノート（/math）」と `docs/math-note-template.md` にある。ここには、それらを使ってページを作る順番と、判断が要る所だけを書く。

## 1. 入力を読む

- 入力（多くは `tmp/input.md`）を最後まで読み、ノートの単位を決める。1 ノート = 1 つの概念（「写像」「有限集合」）。
- 既存のノートに足すべき内容か、新しいノートかを、`src/content/math/` のタイトルと description を見て決める。迷ったら本人に聞く。
- 入力にない証明・理解・状態を作らない。足りないものは確認事項として最後に報告する。

## 2. 置き場所を決める（分野と並び順）

- **分野**（`topic`）：`src/data/math.json` の `fields` の id。分野は「基礎から応用」の順に並んでいる（論理学 → 集合論 → 実数 → 位相空間論 → 組み合わせ論）。合う分野がなければ、勝手に作らず本人に聞く。
- **分野の中の順**（`order`）：依存関係の順にする。証明で使うノートを前、使う側を後ろに置く。
  - 新しいノートの証明が使う既存のノートを洗い出し、その全部より後ろの `order` を付ける。
  - 既存のノートが新しいノートの結果を使うなら、新しいノートをその前に入れる（既存の `order` をずらす）。
  - 別の分野のノートを使うのは構わない（例：集合論のノートが「整数と実数」を使う）。分野の順は動かさない。

## 3. 書く

- `docs/math-note-template.md` を写して `src/content/math/<slug>.md` を作る。slug は英語の概念名（`finite-sets`）。
- タイトルは日本語の概念名（「有限集合」）。英語名は `aliases` に入れる。
- ブロックの種類を正しく選ぶ：主張は definition / theorem / proposition / lemma / corollary、主張が成り立たないことを示す例は `counterexample`、それ以外の具体例は `example`。
- 他のページからリンクする主張には `{#id}` を付ける。証明で使った結果は `[補題 1](#lem-xxx)` や `/math/<slug>#id` のリンクにする。このリンクが依存関係と並び順の検査の材料になる。
- 参考文献の章・節（`sources` の `location`、`textbook`）は、資料で確かめたものだけを書く。

## 4. 確かめる

```sh
npm run check && npm test && npm run build && npm run check:links
```

ビルドの出力で `[math] 並び順の警告` を探す。

## 5. 並び順の警告が出たら：本人に判断してもらう

警告は「分野の中で、証明が後ろのノートを使っている」という意味。Claude は自分で決めず、AskUserQuestion で本人に選んでもらう。質問には、どのノートのどの節（証明）が後ろのどのノートを使っているかを書き、次の選択肢を出す。

1. **順を直す**：`order` を入れ替えて、使われるノートを前にする。ほかの依存関係と矛盾しないか（入れ替えで新しい警告が出ないか）を確かめてから提案する。
2. **内容を移す**：後ろのノートを使っている節や命題を、そのノートの側へ移す。参考文献でもそちらの節にある内容なら、これが自然なことが多い。本人の証明は文面を変えずに移し、アンカーとリンクを直す。
3. **今の順のままにする**：使う側のノートの frontmatter に、理由を書く。

   ```yaml
   usesLater:
     - note: finite-sets
       reason: "8 節だけが有限集合を使う。直積の定義は写像より前に要るので、この順のままにする"
   ```

選ばれたものを反映したら、もう一度ビルドして警告が消えたことを確かめる。`usesLater` に書いた相手を使わなくなると「usesLater から消してください」という警告が出るので、そのときは消す。

## 6. 報告する

- 作った・変えたノート、付けた `order` とその理由（どのノートを使うから、この位置にしたか）。
- 並び順の警告と、本人が選んだ判断。
- 確認事項（入力になかったもの、証明の飛躍、確かめられなかった参考文献の節）。
- 確認コマンドの結果。
