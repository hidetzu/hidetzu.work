# 数学ノート（/math）の編集ルール

数学の思考と証明は本人が行う。Claude Code は、編集・構造化・表示の改善を担当する。
書式（frontmatter、ブロック、`origin` の属性、依存関係）の仕様は README の「数学ノート（/math）」と ADR 0002〜0006 にある。ここでは繰り返さない。

## 入力

- 入力は、ChatGPT が作った学習サマリーと、本人が書いた Markdown（多くは `tmp/input.md`）である。
- 入力に書かれていない証明・理解・学習状況を創作しない。入力にない内容が必要なら、足さずに確認事項として報告する。
- 入力が途中で切れている、または誰が書いたか読み取れない箇所は、推測で埋めずに本人に聞く。

## 本人の証明の扱い

- 本人が証明したものは `:::proof{origin=self}`（レビューを経たものは `self-reviewed`）にする。「AI が補った証明」（`origin=ai`）として扱わない。
- 本人の証明を、別の証明に置き換えない。論理の流れと場合分け、使っている結果は原文どおりに保つ。
  直してよいのは表記だけである。文章を整えたら `text=ai` を付ける。
- 証明が不十分な箇所や論理の飛躍は、黙って直さない。ノートには原文のまま載せ、確認事項として報告する。
- 出どころが分からない証明に `origin` を推測で付けない。本人に聞くか、`:::proof` にしない。

## 学習段階の区別

次の 3 つを混同しない。

| 段階 | ノートでの書き方 |
| --- | --- |
| 本人が証明済み | 主張のブロックと `:::proof{origin=self …}` |
| 理解済み・証明は未実施 | 主張と説明だけを書き、`:::proof` は付けない。教科書の証明を読んで理解したものは `origin=textbook` |
| 未解決 | `:::question`。途中まで考えた証明は `:::attempt`（足りない所を明記する） |

- frontmatter の `status` は本人の自己申告である。根拠なく変えず、新しいノートで判断できないときは控えめな値にして報告する。

## 数学的な正確性

- 数学的な正確性と論理の厳密さを、読みやすさより優先する。
- 原文の数式・記号・論理構造を正確に保つ。記号を言い換えるときは、意味が変わらないことを確かめる。
- 定義域・境界条件・量化の範囲（$\forall$ / $\exists$ の対象）・和の添字の範囲を確認する。
  曖昧なところは補わずに報告する。
- 似た主張を混同しない（例：示したのが特別な場合なのか、一般の定理なのか）。
- 章・節・定理番号・ページ番号は、本を見て確かめたものだけを書く。教科書の本文や証明を転載しない。

## 構成と既存ページ

- 新しく書く前に、既存ノート（`src/content/math/`）との重複を確認する。重複が大きければ、統合や移動を提案する。
  ノートを統合して URL がなくなる場合は、`public/_redirects` に 301 を足す（ADR 0006）。
- 1 つの大きな主題を 1 ページにする。
- 参照は「後の証明 → 前提の定義・定理」の一方向にする（ADR 0006）。前提の側のノートに後続での使い道を書かない。
- 学習の経過・今後の予定・「このノートの書き方」のようなメタな記述は、本文に残さない。
- Math Notes は特定の教科書の翻訳・要約ではない。導入文や description は「このノートで扱う概念」を中心に書き、「Munkres の第○章をまとめた」のような教科書に従属した書き方をしない。
  Munkres の定理・演習を直接扱う箇所では、番号と対応をはっきり残す（ADR 0008）。
- 「（補足）」は、読者の理解を助けるための追加の説明（直観的な説明、具体例、反例、別の証明など）の印にする。
  参考文献の範囲内か範囲外かは frontmatter の `sources` の `note` に書く。誰が書いたかは `origin` / `text` で示す。
- 参考文献は実際に参照したものだけを書く。原著の文章を訳したり、言い換えただけの文で説明したりしない。
- 依頼の範囲外のノートは変更しない。

## 表記と整合性

- 数式は KaTeX（`$…$`、`$$…$$`）で書く。見出しの番号、アンカー（`def-` / `thm-` / `prop-` など）、リンク、ナビゲーションの整合を保つ。
- アンカーやスラッグを変えるときは、ほかのノートと `src/data/math-notation.ts` からのリンクも直す。
- 図は軽量なインライン SVG（`.math-figure`）で描き、新しい依存ライブラリは足さない。

## 完了前の確認

- `npm run check`、`npm test`、`npm run build` をすべて通す。
- `dist/math` で、リンクとアンカーが切れていないことを確かめる。
- 表示を変えたときは、スマートフォン幅・PC 幅・ダークモードで、はみ出しがないことを確かめる。
- 報告には、変更したファイル・内容と、確認事項（証明の不備の疑い、出どころが不明な箇所、重複・統合の提案）を分けて書く。
